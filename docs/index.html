01What it is

A coding agent with a second brain and a harness

VIKI Agent runs a coding agent on the model you choose and adds two parts around it: a Markdown vault that grows into a second brain as you work, and Decision, a harness that picks the moment for work and hands waiting Kanban cards to your Bots.

Your vault · the second brain

Knowledge that compounds

Holds
Markdown you own: projects and their tasks, sources, knowledge notes, maps, daily notes and Kanban cards. An active project’s overview, such as 10-projects/website/website.md, gives Decision a goal. Your chats there run with the vault’s own instructions and skills; a Bot uses its skills and its own instructions.
Grows
With the skills a Start with VIKI vault includes:
  • /capture/inboxCatch a thought in 00-inbox/, then file it.
  • /learn/researchTurn a link, a file or a question into source notes and cited knowledge notes.
  • /connect/lintLink related notes; report dead links, orphans and stale facts.
  • /retroTurn your corrections and repeated wins into changes to the vault’s memory and skills. Only what you approve is applied.
Shows
The Vault view’s overview shows what changed lately, captures waiting in the inbox, knowledge counts by status and confidence, and maps and tags.

Decision · the harness

Work between your requests

Reads
Your vault and chats: due and overdue tasks, stalled projects, inbox captures, Kanban cards, waiting approvals and idle code changes, weighed against your active projects.
Orchestrates
Chief turns your request into a Kanban card for a seat. When the card waits, VIKI can start that seat’s tested routine in a fresh chat, or offer it to you first. Checker checks the result against the card’s Done-when items.Meet the core team ↓
Authority
Each kind of work has its own grant, daily limit and holds: Allowed can start it, Ask first offers it to you. TypeSafe’s optional Decision model (JEV) only rates items; without it, local rules still run.
Improves
Offers improvements to your vault and to itself, such as a skill from a repeated workflow, a literature note for a captured source, a link between two notes or better wording for one of its own questions. Nothing changes until you approve or send it.

Coding agent · your model

Does the work, on the model you choose

VIKI Agent runs Claude Code, unmodified, as its agent, with the instructions, skills, hooks and permissions of the folder it runs in; a Bot skips the vault’s instructions and gets its own. Its permission requests reach you as cards: Allow once or Deny.

A Bot is the same agent with a profile, a vault and a conversation of its own. Each routine run gets a fresh chat.

Bring your own model

  • Claude Code sign-inYour Claude plan, an API key or a cloud provider
  • MagpieA model or routing group from the model router VIKI Agent runs for you
  • Cloud APIIts endpoint, model ID and key
  • Local model serverCan keep inference on your computer

Add one in Settings › Providers and select Use for new chats. It needs a tool-calling model that speaks Chat Completions, the Responses API or Anthropic Messages, and saved keys are encrypted on this computer. Agents › Profiles chats, routine runs and inbox suggestions use Claude models; a Bot’s own chats use the connection its profile pins, if it pins one.

Use your own model ↗Profiles, Bots and routines ↗

Which safeguard applies? Your Claude Code hooks govern the CLI operations they cover. VIKI Agent’s own note saves have separate checks: a save stops if the note changed elsewhere first (your draft stays) or if the new name is taken.

The starter vault includes deny rules but ships no guard hooks. A vault isn’t a sandbox, and VIKI Agent doesn’t guarantee that a model’s output is correct. Read the integrity model ↗

02Set up

Install and launch

Clone the VIKI Agent repository on GitHub, then run four commands from its root.

You’ll need

  • A supported desktopWindows 11 · macOS on Apple silicon · Linux x86_64/aarch64 with glibc 2.28 or later and X11 or Wayland
  • Build toolsPython 3.14 or newer, uv, Node.js 24 and npm
  • A window to run inA Chromium-family browser, or VIKI Agent’s own Electron window
  • Claude Code and a modelClaude Code’s own sign-in, or your own cloud API or local model server
PowerShell / shell · repository root
# 1  Install the locked Python dependencies
uv sync

# 2–3  Install and build the interface
npm --prefix frontend ci
npm --prefix frontend run build

# 4  Open VIKI Agent
uv run viki-agent

A fresh checkout has no frontend/dist/ until the build finishes, and the app needs it.

Then

  1. 1
    Follow the setup guide

    Sign in or connect a model, then create a vault, open a folder, or chat without one. uv sync already installed the Claude Code the app runs.

  2. 2
    Connect a model

    Chats use the sign-in Claude Code is set up with; if it has none, Sign in uses your Claude plan. Or add your own model in Settings › Providers and pick Use for new chats.

  3. 3
    Optional: Decision’s model

    The model behind Decision has its own saved key under Decision model.

Platform extras and the Electron window
  • Linux also needs git, xdg-open and Secret Service via secret-tool.
  • macOS keeps the app’s sealing key in the login Keychain.
  • Browser discovery: Edge on Windows; Edge, Chrome or Chromium on macOS; non-confined Edge, Chrome or Chromium on Linux (snap and Flatpak launchers are skipped).
  • No browser? After building, npm --prefix desktop ci then npm --prefix desktop start opens the Electron window. On Linux, Electron’s sandbox helper must belong to root first; Known issues has the two commands.
Full prerequisites and checks ↗
Upgrade the app

Close VIKI Agent and wait for its process to exit, update your checkout (git pull), then repeat the install and build commands. Back up VIKI Agent’s data first: an older version refuses to open app data that a newer version has updated.

Upgrade details ↗
Close the app or stop work
  • Closing the last window gives running chats up to 300 seconds to finish.
  • Waiting permission requests are denied while no window is open.
  • To end work on purpose, use the chat’s Stop first.
  • On macOS, quit the app browser with ⌘Q if it stays open.

Chat or Chief?

Chat when you want to steer. Chief, the Bot that routes requests to the team, when you want to hand off an outcome. You can use both.

Chat · you steer

  • Ask, inspect code, compare notes or direct a change

Meet the core team

Seven seats, each with its own job, icon and color. A Start with VIKI vault already has all seven in Bots, and each starts nothing until you send it a message.

  • Front door

    Chief

    Turns your requests into Kanban cards for the right seat. It routes; it doesn’t do the work.

  • Manager

    Ops

    Runs the daily standup and the weekly review from its own routine, and takes no card.

  • Specialist

    Research

    Works cards tagged owner/research: sources, literature notes and research briefs.

  • Specialist

    Writer

    Works cards tagged owner/writer: drafts that wait for you to send or publish.

  • Specialist

    Engineer

    Works cards tagged owner/engineer: specs, scripts, code reviews and fix plans.

  • General desk

    Desk

    Works cards tagged owner/desk: small one-off jobs no other seat owns.

  • Quality gate

    Checker

    Checks finished work against its Done-when items and evidence, then reports PASS or FAIL.

Your own Bots get faces too. A Bot without an uploaded avatar gets a drawn robot face, with its head, visor, eyes and emblem drawn from its profile. A new Bot gets the least-used of eight colors. Avatars and colors ↗

Or put several Bots in one thread

  • Open Bot threads → New Bot thread and pick up to 6 Bots. Chief and Checker are selected by default.
  • Choose the first Bot with To, then Send to team. Bots hand work to each other, and the thread finishes when Checker reports PASS.
  • While a Bot works, Steer sends it your message at once (this needs Claude Code 2.1.281). Stop or Esc interrupts it.
Shared Bot threads ↗

Where’s the work? Kanban, in the left sidebar, is a read-only view of notes in kanban/: select a card to open its note, then edit the note or ask a Bot. Only cards directly in kanban/ show there (Bots). A routine’s Open session opens that attempt’s own chat, separate from the Bot’s regular conversation.

When

More in What VIKI may do

  • Look on my behalfLooks over a trusted code folder’s changes that have sat for a day, in a plan-mode chat.
  • Take a second look at my workReviews a long or corrected task in the chat you have open and proposes one finding as a plan.
  • Overdue tasksPlan next steps for my projects also checks tasks three or more days overdue.
  • Prepare draftsA handoff for a nearly full chat, or literature notes for pages its last reply fetched. A draft waits for you to send it.
  • Run my saved checksReruns the checks you ran before when a trusted folder moves to a new commit.
  • Launcher alertsStopped saves, deleted notes about to expire, chats waiting five minutes for you and messaging bridges that stopped.

VIKI holds its own starts in your quiet hours, when your plan use reaches the level set in Pause automatic starts at Claude plan usage (80% by default), while another chat VIKI started is open, or for a better moment. A held item still offers its start, and Why now says what holds it. Chats VIKI starts read Started by VIKI, and Stop all stops them together. In a protected vault VIKI only prepares plans; in a read-only vault it starts no chat of its own.

08Keep context current

Give the next session a reliable start

Long-running work collects old assumptions. Check the source, context and outcome again as the project changes.

What the app does

Records the version you approved

An Active memory records this device’s approval of that exact version. Corrections and retirement have their own review controls.

Your part

Claims can go stale

A memory can stay Active after its source changes. Check the current note and the memory’s status and sources before reuse.

Safeguards and their limits ↗

How do Bots keep an ongoing workflow organized?
  • A Bot links a profile and a persistent vault workspace to one reopenable conversation and its own routines. Each routine run has its own conversation.
  • Several Bots can work as a team through cards in the vault’s kanban/ folder. Bots lists the seats: Chief, Ops, Research, Writer, Engineer, Desk and Checker.
  • A Start with VIKI vault already has all seven. Add missing Bots under Core team adds every missing one; neither sends anything. In another registered vault, Open conversation on a seat creates its profile and Bot if missing, and sends nothing.
  • A routine set to Only when a card is waiting skips its scheduled time when no todo card in kanban/ is tagged for its seat. VIKI’s launcher lists the cards that need you.
  • With Claude Code’s auto memory on, a Bot’s conversations and routine runs in any vault keep their memory in that Bot’s own folder, which Claude Code writes under its own permissions: bot-memory/ in an ordinary vault, otherwise VIKI Agent’s data folder, outside the vault.
  • Saved history can contain material that has left the model’s active context.
  • A Bot gets its profile instructions in Claude Code’s system prompt each time its chat starts, so compaction doesn’t drop them. An Agents › Profiles chat gives them as first-turn text, which compaction can drop: check Context & loadout, restate current requirements, or start a New conversation.

10Privacy and control

Privacy and permissions

The interface and server run on your computer, and Claude Code runs tools under your permission rules.

What leaves your computer

Claude Code sends chat context through its provider connection. Decision sends permitted titles, evidence and bounded history to its model service. Chats and runs VIKI starts send what they read through Claude Code too.

Set the send level and Never-send folders or tags under What leaves this computer.

What an approval allows

Tool cards offer Allow once and Deny. A stored answer isn’t a blanket permission.

Memory activation, note saves and code integration each have their own review.

Limits of local protection

Per-launch authentication, origin checks and sealed state don’t isolate you from a malicious process running as the same OS user.

Plaintext exports and note backups need separate care.

12Troubleshooting

Get unstuck

Keep the exact message. It usually points to a better next step than restarting or resending.

The window doesn’t open
  • Read the launcher’s message and exit code.
  • Not built yet? Run npm --prefix frontend run build.
  • Port 8765 is fixed: another process on it prevents startup.
  • If the alert names the browser, check browser discovery.
Launcher messages and fixes ↗
The window opens, but I can’t send

Check the provider readiness state. A missing login, a missing CLI or a billing conflict can let the window open but refuse a session start. Follow the repair shown, then use the offered action.

Provider readiness and error cards ↗
A send or Stop has an unclear outcome
  • Check the conversation and affected files before resending; the app doesn’t retry turns automatically.
  • A forced Stop can leave partial work.
  • A session ended before its first transcript existed may need a new conversation.
Known stop and resume limits ↗
I need to report a problem
  • Open an issue in the GitHub repository with the OS, VIKI Agent version or commit, Claude Code version, exact message, steps and expected result. Report a suspected vulnerability privately, as the repository’s security policy describes.
  • Use Diagnostics for the app’s bounded report, and review its preview before sharing.
  • Leave out raw transcripts and private vault content by default.
